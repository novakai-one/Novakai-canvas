# Templates

Own immutable recipe/theme versions, the `.theme` text grammar, exact pin selection, admission plans and independent recipe expansion. Enter through `contract/index.ts`; `composeTemplates` binds deterministic hashing and requires syntax/token owner ports. No presets or diagram documents are physically written here.

`planAdmission` creates one new version or returns an identical no-op; different content cannot replace an existing version. `instantiate` returns ordinary editable intent with the exact reachable media/theme manifest. It does not create live inheritance.

`readThemeSource(text)` reads a `.theme` file into a typed theme admission and its body, mono and strong font requests. It is pure and fails with `invalid-theme` or `duplicate-token` (`ThemeSourceFailure`). The host reads the file, stages the fonts and submits the admission; Design System checks token names and values at admission.

Starter DSL sources: `resources/recipes`. Contract cases test Templates policy with explicit codec fixtures.
